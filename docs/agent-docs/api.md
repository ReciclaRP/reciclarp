# API reference (`api/`)

Everything relevant is in one file: `api/src/server.js` (~800 lines). The DB
schema and seed data live in `api/src/db/schema.js`.

## Running

```bash
cd api && npm install && npm run dev   # node --watch src/server.js
```

Environment variables (also read from `api/.env` via dotenv):

| Variable | Default | Purpose |
| --- | --- | --- |
| `RECICLA_API_PORT` | `3000` | Listen port. |
| `RECICLA_RESEND_SECRET` | unset | Resend API key. **Unset = guest mode**: OTC codes go to the pino log instead of email. |
| `RECICLA_WEBAPP_URL` | `http://localhost:5173` | Allowed CORS origin. |
| `RECICLA_ADMIN_EMAIL` | `test@example.com` | Email of the seeded admin (id 0, `ong=1`, `validated=1`). |
| `RECICLA_ESCALATION_TOKEN` | autogenerated + logged | Defined but currently unused by routes. |

The SQLite file is `api/recicladb.sqlite`; on first boot the schema is created
and seeded with the admin account and 8 real "ecopontos" from Ribeirão Preto
(seed data in `api/src/db/schema.js`).

## Cross-cutting behavior

- **Response envelope (always):** `{ type: "okay" | "error", description?, ... }`. Keep this shape.
- **All routes POST** except `GET /api/ping` (health check).
- **CORS** restricted to `RECICLA_WEBAPP_URL`.
- **Rate limits** (express-rate-limit):
  - global: 100 req / 15 min per IP;
  - `/auth/login`, `/point/create`, `/point/update`: **1 req / 2 min per IP** —
    this will block repeated manual testing.
- Auth on protected routes is checked per-handler (no middleware): the handler
  constructs `Account(email)` and compares `account.token_read() === token`
  from the request body.
- Validation uses a module-level `EMAIL_REGEX`; points validate coordinates,
  description, hours, and material flags.

## Routes

| Route | Auth | Purpose |
| --- | --- | --- |
| `POST /auth/login` | — | Send OTC code to an existing, non-banned email. |
| `POST /auth/token` | — | Exchange email + OTC code for a token. |
| `POST /auth/check` | token | Return `{ email, name, id, banned, ong }` if token valid. |
| `POST /auth/delete` | token | Delete the caller's account (fails if banned). |
| `POST /point/list` | — | List points. |
| `POST /point/create` | token | Create a point (`approved=0`, pending ONG moderation). |
| `POST /point/update` | token | Update a point (ONG moderation path). |
| `POST /point/remove` | token | Remove a point. |
| `POST /report/create` | token | File a citizen report about a point. |
| `GET /api/ping` | — | Health check. |

## Key classes (server.js)

- `Tickets` — in-memory email → 5-digit OTC code map (`ticket_queue`).
- `Tokens` — in-memory email → random token map (`token_list`), with `invalidate`.
- `Account` — wraps a user row by email; methods include `exists()`,
  `__is_banned()`, `is_ong()`, `send_loginmail()`, `token()`, `token_read()`,
  `get_id/get_email/get_name`, `delete()`.
- Helper `bton(b)` converts booleans to SQLite 0/1.

## Adding a route

1. Match the existing handler shape: log with `logger.info`, validate body
   fields first and return the `type: "error"` envelope on malformed input.
2. Reuse `Account` for auth checks; do not introduce middleware silently.
3. If a new limiter is needed, follow the pattern of `points_limiter`.
4. Update `docs/agent-docs/api.md` route table (this file) in the same change.
